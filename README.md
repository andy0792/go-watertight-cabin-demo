# go‑watertight‑cabin‑demo
> 
> 项目名：软件水密隔舱演示（限流 · 熔断 · 降级 · 故障注入）
> 英文名：go-watertight-cabin-demo
> 主旨句：一个舱进水，整艘船不沉。演示故障隔离原理，看单个故障如何不拖垮整体应用。
>
> 非开发人员仅靠点击按钮、修改网页数字就可以理解分布式故障隔离原理。  
> 类比轮船水密隔舱：单个舱故障进水，不会造成整艘船沉没；业务模块故障，不会把整个应用拖垮，实现故障隔离。
> 
> Go 实现的网页可视化教学 Demo，演示水密隔舱模式（Bulkhead）+ 信号量并发限流 + 熔断器 CircuitBreaker + 业务降级 Fallback + 网页故障注入。
>

## 📖 项目简介
本项目是**教学演示项目**，软件水密隔舱思想源自轮船水密舱设计：**某一个业务模块发生故障，不会把整个应用拖垮，实现故障隔离，阻止故障雪崩**。

✅ 完整实现分布式高可用三板斧：**限流、熔断、降级**
1. **信号量并发限流**：每个业务独立隔离舱，设置最大并发，流量超阈值快速拒绝，避免 goroutine 大量堆积。
2. **熔断器 CircuitBreaker**：三状态机 `Closed(正常) / Open(熔断阻断) / HalfOpen(半开试探)`；支持失败百分比阈值、熔断冷却时间、半开试探请求配额控制；支持**简单计数 / 滑动时间桶**双统计窗口，每舱独立切换配置。
3. **业务降级 Fallback**：熔断器打开后执行兜底函数，返回模拟缓存数据，在下游故障时保障对外接口可用。
4. **网页故障注入**：浏览器页面直接配置故障开关、故障百分比，**不用修改代码、不用重启服务**，模拟下游报错、服务不稳定、完全故障等工况。
5. **Canvas 时序泳道可视化**：记录限流、熔断、降级、配置变更全部结构化事件；支持事件智能堆叠、溢出聚合、事件过滤，直观复现事件发生时序。
6. **一键场景演示**：内置3套预设场景，一键完成参数与故障配置，适合课堂教学、线上技术分享演示。

> ⚠️ **重要声明：本项目仅用于学习教学，禁止直接复制用于生产环境。**
> 生产系统还需要业务错误类型过滤、Prometheus指标告警、身份鉴权、panic保护等能力。

### 🧩 内置3个业务隔离舱
| 舱名称 | 演示主题 | 特性说明 |
|---|---|---|
| 下单核心舱 | 并发限流 | 模拟核心交易业务；无降级；不可故障注入，业务永远返回成功 |
| 营销舱 | 熔断 + 降级兜底 | 普通业务；支持故障注入；熔断触发执行fallback降级返回缓存模拟数据 |
| 报表辅助舱 | 熔断器完整生命周期 | 易故障的下游业务；支持故障注入；无降级，熔断直接返回错误 |

## 🏗️ 系统架构
```
浏览器前端 index.html（纯静态，无编译，仅做UI交互）
        ↓ HTTP Fetch AJAX
Go后端 go‑go.go
    ├─ BusinessCabin 水密业务隔离舱（3个实例互相完全隔离）
    ├─ CircuitBreaker 熔断器三状态机实现（支持双统计窗口）
    ├─ semaphore.Weighted 信号量，实现舱级别并发限流
    ├─ 故障注入模块：内存存储每个舱故障开关 & 故障百分比
    ├─ Metrics指标统计：总任务、成功、限流拒绝、熔断拒绝、业务报错、降级次数
    ├─ TimelineEvent 结构化时序事件模块，输出事件数组给前端Canvas绘图
    └─ HTTP REST接口 + 静态文件服务托管前端页面
```

## 🚀 快速运行
### 环境要求
Go 1.21 及以上版本

```bash
# 1.克隆代码仓库
git clone https://github.com/andy0792/go‑watertight‑cabin‑demo.git
cd go‑watertight‑cabin‑demo

# 2.配置国内代理，拉取第三方依赖
go env -w GOPROXY=https://goproxy.cn,direct
go mod tidy

# 3.源码方式启动服务
go run go‑go.go
```

打开浏览器访问：`http://127.0.0.1:8080`
> 💡建议使用无痕窗口，避免浏览器缓存造成页面渲染异常。

### 编译打包说明
> ⚠️ 重要：原生 `go build .` **只会编译 Go 源码，不会自动把 index.html 打包进 exe 二进制**。
> - 现象：单独移动 exe 到其他目录，访问网页会出现 404 找不到页面。
> - 两种方案：
>   1. **本地文件模式（开发调试推荐）**：exe 与 index.html 放在同一目录下运行；修改 HTML 无需重新编译，刷新浏览器即生效。
>   2. **embed 打包模式（分发演示推荐）**：源码中增加 `//go:embed index.html` 指令，编译时将 HTML 打进 exe；单文件即可运行，但修改 HTML 必须重新编译。

```cmd
# 编译生成 exe 可执行程序
go build .
```

## 🎮 快速上手做演示实验
> 💡课堂演示优先使用页面上方紫色**一键场景按钮**，省去手动填写参数。

1. **场景A‑限流挡流量**
演示并发限流；现象：限流拒绝计数上涨，熔断器保持绿色正常；限流拒绝不会计入业务失败，不会触发熔断。

2. **场景B‑降级保自己（熔断+降级）**
营销舱开启100%故障，制造业务报错打到熔断Open状态；**在熔断冷却窗口期内发送请求**，观察降级兜底现象。

3. **场景C‑熔断防雪崩**
报表舱模拟下游完全故障，完整复现熔断器生命周期：
`Closed → Open → HalfOpen → Closed`
直观看到：报表舱熔断变红，其余舱不受影响，体现**水密隔舱故障隔离**。

通用操作流程：
1. 点击场景按钮自动配置参数与故障注入；
2. 点击【①发起第一轮批量请求】产生业务流量；
3. 根据演示场景，执行等待窗口期、第二轮试探请求；
4. 观察舱卡片底色、指标数字、Canvas时序泳道图；
5. 实验完毕，点击【重置所有舱状态】恢复初始。

> 💡进阶实验：可切换「简单计数 / 滑动统计」两种窗口模式，对比不同失败率判定逻辑的行为差异。

## 📡 HTTP接口简要列表
|接口|方法|功能|
|---|---|---|
|`/api/status`|GET|获取全部舱配置、指标、故障配置、日志、时序事件数组，前端轮询调用；含`cb_open_remain_ms`（Open状态距进入HalfOpen的真实剩余毫秒，供前端冷却倒计时）|
|`/api/applyConfig`|POST|更新业务舱配置参数（含统计窗口类型、滑动窗口时长）|
|`/api/setFault`|POST|设置舱故障注入开关、故障百分比|
|`/api/runFirst`|POST|发起第一轮批量模拟请求|
|`/api/waitHalfOpen`|POST|等待熔断冷却窗口期|
|`/api/runSecond`|POST|发起第二轮半开试探请求|
|`/api/reset`|POST|完整重置全部舱、指标、日志、时序事件|
|`/api/resetMetricsOnly`|POST|仅清空业务指标，保留熔断器状态与时序事件|
|`/api/clearLogs`|POST|仅清空文本日志与时序事件，不改动业务舱状态|

## ✨ 特性亮点
- 🎨 可视化教学：舱卡片底色跟随熔断器状态变色；Canvas时序泳道图图形化展示事件流；支持事件堆叠、聚合、过滤。
- 🎯 一键场景，降低演示翻车概率；任务运行按钮自动置灰防护。
- 🔧 网页端完整可配置：并发、熔断阈值、窗口大小、冷却时间、半开试探配额、模拟RTT延时、故障概率全部网页可调。
- 📊 双统计窗口模式：支持简单计数窗口、滑动时间桶窗口两种熔断统计模式，每舱独立切换，可直观对比两种失败率判定逻辑差异。
- ✅ 前端参数合法性校验：并发≥1、百分比0-100、冷却≥1、半开试探≥1、耗时≥0，非法输入红框+toast拦截，不提交后端。
- ⏳ 熔断Open冷却倒计时：以真实后端剩余时间`cb_open_remain_ms`为准，网页显示「⏳ Xs 后进入半开」，消除UI快照与后端真实状态不一致演示坑。
- 🔒 熔断状态原子切换：状态切换点采用 CAS 原子操作，并发下保证每个切换只记录一次，避免重复日志。
- 📝 真实风格业务报错池：每个舱内置多组真实场景错误模板，业务报错贴近生产环境。
- 📊 完整指标：业务指标 + 熔断器窗口内部计数，可直观看到熔断触发的双条件。
- 📝 结构化时序事件记录，便于复现、分析故障流程。

## ⚠️ 已知局限（Demo特性）
1. 全部指标、配置、时序事件存储在内存，进程重启全部丢失。
2. 所有业务异常默认全部计入失败统计；生产环境需按错误类型过滤（如参数错误、鉴权错误不计入熔断统计）。
3. 没有鉴权认证，不适合公网暴露。
4. 仅进程内部隔离，无法解决CPU打满、OOM、机器宕机类问题。
